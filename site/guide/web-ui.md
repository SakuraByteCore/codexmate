# Web UI 集中管理

`codexmate run` 起的 Web UI 是协作中枢:provider 切换、多工具配置方案、会话统一视图、Skills 与 Prompt 编辑都在一处。

侧边栏固定使用紧凑折叠布局，不再提供展开或折叠按钮。保留导航文字、语言切换和设置入口；底部语言入口只显示当前语言名，不显示“语言：”前缀。历史侧边栏偏好不再改变布局。

## 版本更新提醒

点击侧边栏或移动端顶部的“有新版本”，在当前页面查看当前版本、最新版本与 `codexmate update`。点击“复制”复制命令；复制失败时可手动选中命令。点击关闭、遮罩或按 `Escape` 关闭弹窗，键盘焦点返回版本入口。

点击与复制不会执行更新。在运行 Codex Mate 的主机终端执行命令，更新成功后重启服务；远程访问时不要在访问设备上执行。没有新版本时点击检查更新，检查失败时点击重试。

## 启动选项

```bash
codexmate run                # 默认 127.0.0.1:3737,自动开浏览器
codexmate run --no-browser   # 仅服务,不开页面(调试 / CI)
codexmate run --host 127.0.0.1
CODEXMATE_PORT=8080 codexmate run
```

端口不可用自动顺延(`3738`/`3739`...)。

## 局域网访问

默认只允许本机访问。需要从同一局域网的另一台设备访问时，先设置访问令牌，再显式监听所有网卡：

```bash
CODEXMATE_HTTP_TOKEN='<高强度随机值>' codexmate run --host 0.0.0.0
```

`localhost`、`127.0.0.0/8` 和 `::1` 属于回环地址。监听其他地址时必须设置 `CODEXMATE_HTTP_TOKEN`；未设置会直接启动失败，错误信息包含 `CODEXMATE_HTTP_TOKEN`。

然后用 `http://<本机局域网IP>:<端口>` 访问。终端会显示最终监听地址和端口。远程 Web UI 保留浏览器 Basic Auth 兼容：浏览器弹出登录框时，用户名可留空，密码填写访问令牌。脚本访问远程 Web UI 或 API 时，可使用以下任一种请求头：
```bash
curl -H "Authorization: Bearer <访问令牌>" http://<本机局域网IP>:<端口>/api
curl -H "X-CodexMate-Token: <访问令牌>" http://<本机局域网IP>:<端口>/api
```

远程 `/bridge/` 请求强制使用 `Authorization: Bearer <访问令牌>`；缺失或令牌错误会返回 `401`。回环地址访问 `/bridge/` 保留现有兼容行为，不强制 Bearer。

`CODEXMATE_ALLOWED_IPS` 可选填逗号分隔的 CIDR 或单个 IP，例如 `192.168.1.10,192.168.1.0/24`。判断仅依据 `req.socket.remoteAddress`；留空表示不限制来源 IP，配置后非白名单来源返回 `403`。白名单同样作用于回环来源：本机访问需要把 `127.0.0.1` 与 `::1` 一并列入，否则本机请求也会收到 `403`。

访问令牌仅从启动进程的 `CODEXMATE_HTTP_TOKEN` 环境变量读取，需在启动前设置。涉及 Key、配置或 Skills 的远程访问必须保持令牌鉴权开启。

## 能办的事

### Provider 与 Model
- Codex provider/model 切换,带指纹头规范化(Codex CLI 形态请求)。

### Provider 桥
- OpenAI 桥: Codex Responses API 转标准 OpenAI 格式。
- Claude 桥: Claude Code 接 OpenAI Chat Completions 兼容 provider 与 Ollama。
- OpenCode Store: 多 provider 存 `~/.codexmate`,仅激活项投影到原生配置。
- KiloCode 桥: 写 `~/.config/kilo/kilo.jsonc` 保留 Key。

### 模型分配 {#路由组}

这页只决定 Codex／Claude 的模型请求交给谁，不是聊天窗口，不执行任务，不让多个模型共同回答。先选主力，备用可选；默认「主力优先」，主力遇到指定错误时才尝试备用。「轮流使用」按请求轮换，不按用户的一轮对话计数。

首屏提供用途说明和首次使用步骤，成员标注主力／备用或模型编号；已启用状态显示所选组名，只证明配置接入。错误条件、供应商与模型 ID 的解释收进「工作方式与限制」。首次接入后重新启动对应工具，再在工具里提问。

「模型分配」（原「路由」）一级页集中管理 Codex、Claude 与 OpenAI Chat 上游组，沿用当前导航、主题与控件。支持组创建、编辑、删除、成员排序、模型指定和绑定；每种接入目标独立绑定一个组，最多 64 个组，每组 1–16 个不同的供应商/模型组合。成员明细默认折叠，当前绑定组默认展开；点击成员数量查看明细。编辑、删除使用带悬停提示的图标按钮。

1. 在对应配置页添加供应商。模型分配页可直接点击「开启写权限」，沿用现有确认，不自动提权。Claude 供应商需已同步到本地桥接存储；列表为空时提供配置入口。
2. 在「模型分配」选择工具，新建组会预填未重名名称、可用供应商及已有配置中的模型。新增成员优先选择尚未使用的供应商；未知模型保持空白，必须填写。保存前检查缺失字段、不可用供应商和重复成员，失败保留草稿，不发送无效写入。
3. 选择「主力优先」或「轮流使用」。主力优先每次从首个成员开始；轮流使用每次请求轮换首选成员，失败后继续尝试组内成员。
4. 点击「启用此组」完成绑定与显式启用；已有活动桥接时显示同名的「启用此组」，只切换绑定。成员明细保留「仅绑定」，该操作不启用桥接。只有发往本地桥接的请求使用绑定组。配置接管状态不是请求命中或健康检查证据。
5. 当前使用组显示「取消此组」，解除绑定后继续使用原轮询池，不关闭桥接；「恢复工具配置」沿用原配置恢复入口。先解除绑定才能删除组。

编辑已启用的组时，页面提示保存会影响后续请求；当前请求不会重放。取消此组只解除组绑定，不等于恢复接入前的工具配置。

绑定完成但启用失败或状态读取失败时，保留已确认绑定，不自动重试、不伪报成功；页面显示待启用状态与刷新核对提示。操作中禁用重复点击，当前组显示处理中。

回退仅发生在输出开始前的 HTTP 408、429、5xx。其他 4xx 原样返回；输出或流式响应开始后不重放。一次请求只尝试组内成员，不降级到组外供应商。成员缺失、无有效 HTTP 地址或已排除时跳过；全部不可用时返回 503。工具、图片、推理等能力由上游决定，不自动转换成模型不支持的能力。回退会产生额外上游调用，不能视为免费重试。

组文件 `~/.codexmate/routing-groups.json` 只存名称、目标工具、策略、成员供应商/模型、绑定，不复制密钥。保存、绑定、删除携带读取版本，版本冲突时保留草稿，刷新后核对再保存。读取不创建文件；写入采用原子替换。新 API 为 `routing-get`、`routing-save`、`routing-delete`、`routing-bind`；旧桥接 API 与未绑定请求保持原行为。

路由组不属于「撤销最近一次配置」范围。修改组前保留原名称、策略与成员；用编辑恢复原值。恢复文件只限已核对的本地组备份，不覆盖并发修改。首版不含配额路由、意图分类、嵌套组或请求历史。

#### OpenAI Chat API 接入

1. 在「模型分配」选择 **OpenAI Chat**。
2. 在 Codex 配置页管理支持 Chat Completions 的供应商。复用其排除设置与写权限，不要求安装 Codex，不更改 Codex／Claude 的连接配置。
3. 新建模型组，选择主力和可选备用，保存后点「启用此组」。OpenAI Chat 绑定即启用，取消即停用；不提供含糊的「仅绑定」操作。
4. 在 OpenAI 兼容客户端填写页面的 Base URL 和模型 ID `routing`。模型 ID 是固定入口别名，实际供应商与模型按组内规则选择。网页仍不是聊天窗口。

默认 Base URL 为 `http://127.0.0.1:3737/bridge/openai-chat/v1`，更改服务端口或主机后以页面显示值为准。支持 `POST /chat/completions` 与 `GET /models`，后者仅公布 `routing`，不调用供应商、不消耗轮流位置。请求必须包含 `model: "routing"` 与非空 `messages`；真实 JSON／SSE 回复直接透传，工具参数、图片内容、`stream_options` 等由上游决定。没有 Responses、Messages、Embeddings 或 Images 协议转换。不支持嵌套模型分配，内部转发请求再次接入返回 508，防止入口循环。

```sh
BASE_URL='http://127.0.0.1:3737/bridge/openai-chat/v1'
curl "$BASE_URL/chat/completions" \
  -H "Authorization: Bearer $CODEXMATE_HTTP_TOKEN" \
  -H 'Content-Type: application/json' \
  -d '{"model":"routing","messages":[{"role":"user","content":"你好"}],"stream":false}'
```

设置 `CODEXMATE_HTTP_TOKEN` 时，所有 OpenAI Chat 请求（含本机）都需该访问令牌。令牌也可用于现有管理 API，不是仅推理权限；客户端不填供应商密钥。未配置访问令牌时，仅允许本机调用；SDK 需要非空 API Key 时填 `local`，服务器不把客户端 API Key 转发到供应商。上游密钥从已有供应商 `apiKey`／`experimental_bearer_token`／指定的 `env_key` 读取，不复制到组文件，不自动复用 Codex 登录状态。未新增密钥文件、独立权限令牌或跨源 CORS 开放。

未绑定、组文件损坏或组内成员全部不可选时返回 OpenAI 格式 503 错误，不借用 Codex／Claude 或组外池。其他 4xx 不回退；回复开始或客户端取消后不重放。取消组即停用 API，不恢复或改写原工具配置。

旧 version 1 文件可直接读取，缺失 OpenAI Chat 绑定仅在内存补空值，不因读取落盘。保留版本与原目标。回退到不认识新目标的旧代码前，先取消并删除全部 OpenAI Chat 组，保留 Codex／Claude 组，再重启服务。加载本次服务端改动需要重启 CodexMate 服务。

### 配置变更预览与撤销

Codex、Claude、OpenClaw、OpenCode、KiloCode、Pi 共用写入预览。保存或应用配置时查看受影响文件，确认后才写入。预览按规范化字段对比；密钥、认证值与 URL 中的凭据隐藏，格式变化另行标注。

- 在「设置 → 配置写入预览」关闭弹窗后直接写入，仍执行冲突检查与备份。
- 预览有效期为 5 分钟。文件在读取或预览后发生外部修改时拒绝写入；取消弹窗，重新加载配置后再保存。
- 在配置中心点击「撤销最近一次」，查看受影响路径后确认。每种工具保留一次撤销记录；服务重启不清除记录。
- 撤销还原原始内容与权限。本次创建的文件删除；已有目录不删除。外部修改或备份校验失败时拒绝撤销。
- 多文件写入失败时恢复已写入文件。恢复失败会显示路径；不要重复提交，先核对对应备份。

变更记录位于 `~/.codexmate/config-change-last.json`，只保存路径、哈希与备份位置，不保存密钥。原内容沿用相邻的 `*.codexmate-backup-*.bak` 备份。预览编号仅保存在服务内存；服务重启后需重新预览。界面中的配置草稿与预设不属于原生配置文件撤销范围。CLI 命令与旧 API 保持原行为。

### 读取超时与恢复

启动配置读取共用 6 秒总预算；Claude 配置刷新与供应商缓存读取各有 6 秒截止时间。超时会取消客户端请求，解除加载状态。恢复服务连接后重新加载；配置启动失败时刷新页面。

其他长任务不套用上述截止时间。配置保存不自动重试；客户端取消不代表服务端撤销已执行的写入。

## 统一故障诊断

在设置页展开“统一故障诊断”。默认只读取本地 Doctor 结果，不发起模型请求，不启动 MCP。勾选“探测当前 Codex 路由”才联网；MCP 仅检查勾选的已配置服务，执行 `initialize` 与 `tools/list`，不调用 `tools/call`。本地检查不会自动删除配置或执行报告中的命令。

默认显示每项的实际检查时间、状态、耗时与问题摘要，原始证据在“技术详情”中展开；未勾选的远端项显示未检查，不显示通过。单项上限 15 秒，总流程上限 60 秒；取消停止后续项，已发起的有界请求清理后结束。

导出 JSON 或 Markdown 前隐藏认证字段、已知访问令牌、URL 凭据、用户主目录与所选项目绝对路径。报告仅下载到用户选定位置，不上传。当前远端 Provider 检查覆盖激活的 Codex 路由，不宣称覆盖所有工具或供应商。原 `codexmate doctor` 命令保持不变。
